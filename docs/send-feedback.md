# 发送消息的即时反馈

完成日期：2026-10-16。开发基线：`24886e0`。提交信息：`fix(web): show sent messages before server acknowledgement`。

## 问题与修复

| 场景 | 处理方式 |
| --- | --- |
| 输入框清空，消息迟迟不显示 | 已有会话发送时立即显示本地消息和“发送中”，不等待网络或 OMP 输入准备完成 |
| OMP 已接受，但还没有完整回显 | 保留本地消息，显示“已接收，等待显示” |
| 完整用户消息到达 | 移除对应本地消息，显示 OMP 的正式记录；消息开始事件不提前清除占位 |
| 忙碌时发送 | 发送途中显示本地消息，服务端队列确认后交给原有排队列表；仍由 OMP 决定插入或排到下一轮 |
| 发送异常、断线或进程退出 | 保留原文，标明发送未确认，提供复制和移除提示按钮；不自动重发 |
| 切换会话、重连 | 尚未确认或失败的消息保留在原会话 store；新快照中已有正式记录时消除本地重复 |
| 查看旧消息时发送 | 发送后滚到新消息；后续普通流式输出仍沿用原来的滚动规则 |

本地消息与正式历史分开保存，不写入 OMP 会话文件，不改变模型收到的内容。新建会话继续使用原来的即时占位，但占位保留到完整消息结束或快照确认。

消息确认按文本、图片数量和新消息所在位置逐条匹配；队列仅确认新增条目。相同文字连续发送、重复快照或重复队列状态不会提前清除另一条尚未到达的消息。图片随本地消息保留，界面沿用图片数量提示。

本地提示属于当前网页的内存状态，切换对话可以保留，刷新页面会清除。发送未确认时，如需保留原文，请先复制；未确认并不等于服务端一定没有收到。

## 电脑本机延迟排查与历史缓存

2026-10-16，用户补充延迟发生在电脑本机。本阶段开发基线 `dab7fce`，提交信息：`perf(web): reuse unchanged history when messages update`。

| 测量 | 结果与边界 |
| --- | --- |
| 真实 OMP 与本机 WebSocket，本地 `/context` 命令 | 三次返回输出分别为 39.86、1.46、1.42ms；网关回传客户端分别为 0.28、0.23、0.16ms |
| 新建隔离 OMP 会话 | 983.93ms；只代表此次本机启动 |
| 普通消息，锁定 MiMo | OMP 确认 25.14ms，用户消息开始 77.24ms、结束 77.87ms；模型随后报错，没有完整回复或首个输出耗时 |
| 长历史页面 | 100 回合、2000 次工具调用。优化前一组消息确认的 React 渲染累计 107.7ms；优化后单次流式更新累计 4.5ms。这是不同事件，不能据此计算提速比例 |

网关收到普通请求后直接交给 OMP，收到消息帧后直接广播；120ms 合并定时器只刷新状态。普通消息还要经过 OMP 的输入门控、扩展、凭据及上下文准备，具体取决于当前会话配置。上述隔离测量尚未复现用户遇到的秒级停顿，不能把用户会话的原因直接归为网络或某个钩子。

本次减少确定存在的历史重复工作：

- `thread-cache.ts` 复用内容未变化的回合与已完成步骤；内容替换、重连快照、重绕、清空后重新核对。
- `SessionView.tsx` 保持历史回合的操作回调稳定；会话或界面语言变化会重建缓存。
- `Turn.tsx` 缓存处理过程划分、文件改动汇总和时长，避免只切换操作按钮时重复计算。
- 子代理进度仍可更新：`session-store.ts` 为原地更新的子代理数据维护版本，视图按版本更新传入回合的子代理映射。
