# 会话占用与副本

## 使用

CLI 和 Web 打开同一会话时，Web 自动进入只读查看。需要在 Web 中发送消息，先退出持有该会话的 CLI，再点“重新连接”。

更新后执行 `ompweb --restart` 并刷新页面；使用手机远程访问时执行 `ompweb --lan --restart`。已有副本保留，便于确认和保留其中的独立内容。

## 修复记录（2026-10-12）

| 项目 | 记录 |
| --- | --- |
| 问题 | CLI 裸启动后从选择器恢复会话，命令行没有 `--resume` 文件路径；原来的进程表检查漏报占用，Web 启动另一个写入进程，OMP 遇到写入冲突后另存为副本 |
| 现场依据 | Windows 上 OMP 18.8.9；原会话和现有副本均能查到有效系统租约，裸 CLI 进程参数没有恢复路径 |
| 修复 | 从会话文件头读取 ID，按 OMP 的规则推导系统租约名称；Windows 查询命名互斥对象是否存在，Linux 查询 `/proc/net/unix` 中的抽象套接字 |
| 打开流程 | 在启动 OMP 前查询占用，有租约就复用已有自动只读流程；不需要知道具体 PID，旧客户端的强制打开也不能绕过已确认的租约 |
| 只读状态 | 支持未知 PID；未知 PID 的占用状态每 5 秒查询，落盘历史仍每 1.5 秒同步 |
| 查询失败 | Windows / Linux 无法确认占用时阻止启动，返回明确错误，避免把查询失败当作空闲 |
| 数据与依赖 | 不修改 OMP 源码或用户会话、不删除副本、不新增依赖或永久测试文件 |

| 文件 | 职责 |

### 接手注意

租约命名依据 OMP 18.8 的 `session-storage.ts`、`pi-utils/dirs.ts` 和 `pi-natives/file_lock`，已在 Windows 的 18.8.9 实际进程上核对。升级 OMP 若改变此实现，需要核对适配；Linux 实现本次没有在 Linux 真机运行。其他平台沿用进程参数检测和手动只读入口。

这是启动前的占用查询。OMP 未提供原子转交写入租约的 RPC，因此两个独立进程在检查后同时抢占，或 CLI 随后打开 Web 已占用的会话，仍由 OMP 的冲突保护处理。CLI 和 Web 应使用相同的系统租约目录环境；不同 `PI_CONFIG_DIR` 等配置不在当前自动识别范围内。

“副本”依据会话继承关系显示，主动分叉也有继承关系；不能只按标签删除，也不能据此断言每个副本都由冲突生成。从早于本任务的分支接手时，确认上述源码已经合入，不只看文档完成记录。
